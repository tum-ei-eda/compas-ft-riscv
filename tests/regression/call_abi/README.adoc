= Call ABI regressions

These freestanding cases check fault-free calling-convention behavior on RV32 and
RV64. Each case checks independently calculated results, exits with `42` on
success or `17` on an oracle mismatch, and produces no output.

[cols="1,3",options="header"]
|===
|Case |Coverage
|`caller_only` |A protected caller invokes an unprotected callee, retaining a live value across the call.
|`callee_only` |An unprotected caller invokes a protected callee.
|`caller_and_callee` |Both sides of the same boundary are protected.
|`nested_live_values` |Repeated nested calls retain values across multiple calls and stack frames.
|`indirect_calls` |A volatile function pointer invokes two distinct targets, then restores the first target for the next invocation.
|`ten_integer_arguments` |Ten word-sized arguments require argument passing on the stack as well as in registers.
|`ten_integer_arguments_caller_only` |Only the caller is protected, checking that its preservation spills leave the unprotected callee's stack arguments at their ABI offsets.
|`ten_integer_arguments_callee_only_frame_pointer` |An unprotected caller invokes the protected ten-argument leaf with FP forced, isolating FP-relative incoming ABI stack arguments.
|`wide_live_values` |Arguments, return values and values live across a call contain nonzero upper 32 bits; RV32 also exercises register pairs.
|`stack_alignment` |The caller and callee observe 16-byte stack alignment and the caller observes the same stack pointer after return.
|`frame_pointer_calls` |Three protected functions have different frame-size requirements, retain FP-relative locals across repeated nested calls, and restore each caller's incoming frame pointer.
|`frame_pointer_calls_caller_only` |The same calls select only the outer function, exercising a protected caller with unprotected nested callees.
|`frame_pointer_calls_callee_only` |An unprotected outer function invokes two protected nested callees, exercising entry from an ordinary caller and the protected-to-protected boundary.
|`indirect_stack_arguments` |Repeated ten-word calls use a volatile function pointer and different argument values while retaining the first result.
|`nested_stack_arguments` |Both nested call boundaries pass ten words, keeping incoming stack arguments live across an outgoing call; all participating functions are selected.
|`nested_stack_arguments_caller_only` |The same nested calls select only the outer caller, exercising the boundary to unprotected callees.
|`nested_stack_arguments_callee_only` |An unprotected outer caller invokes the two protected nested callees, checking that entry wrappers preserve stack arguments and the caller's live values.
|`nested_stack_arguments_frame_pointer` |The nested ten-argument calls force FP in all functions, checking incoming stack slots and independent shadow arguments from protected callers.
|`nested_stack_arguments_callee_only_frame_pointer` |The same forced-FP calls select only the middle and leaf, exercising ordinary incoming ABI slots and protected-to-protected shadow arguments in one execution.
|`dynamic_stack_arguments` |A large fixed frame and a runtime-sized local array keep values live across ten-word calls, exercising frame-pointer addressing and a moving stack pointer.
|`dynamic_stack_arguments_caller_only` |Only the caller with the large fixed frame and VLA is protected, checking stable preservation slots while calling an unprotected ten-argument helper.
|`realigned_live_values` |A caller with a 64-byte-aligned volatile array and twelve independent live values invokes an unprotected helper with register arguments, checking realigned spill slots separately from stack-passed arguments.
|`signature_join_calls` |A protected caller invokes an unprotected helper in its entry block, in either branch before a join, and after the join; the helper explicitly overwrites both signature registers on RISC-V.
|===

`volatile` inputs and `noinline` functions keep the calls dependent on runtime
loads. Sibling-call optimization is disabled by the shared runner. The stack
alignment case reads the real RISC-V stack pointer in an unprotected leaf helper
with inline assembly; its native smoke build checks only the arithmetic oracle.

The frame-pointer cases set `frame_pointer: true` in their manifest, forcing a
frame pointer even in leaf functions without depending on control-flow protection
to reserve it. All slots in volatile arrays of 3, 5 and 7 words participate in
the results, exercising different frame-size requirements. Constant indices
keep this case focused on frame-pointer preservation across calls.
Post-call loads check that FP-relative locals remain accessible after each pair
of calls. Each input is checked twice against an independent literal result.

The stack-argument cases also check that DMR boundary wrappers and control-flow
signature preservation do not move the outgoing arguments from the ABI offsets
observed by the callee. Caller-only and callee-only selections exercise the two
directions of the selective-hardening boundary with the same arithmetic oracle.
The forced-FP variants reuse the direct and nested arithmetic scenarios. They
check that incoming fixed stack slots retain their entry-frame addresses when
EDDI allocates separate primary and shadow frames. The nested variants
keep arguments nine and ten live across another ten-argument call, with both
protected and ordinary callers entering the protected middle function.
The dynamic-frame case uses a 1024-word volatile fixed array and a variable-length
volatile array. Its calls consume both stack-passed arguments and local values;
the final result checks values retained in both arrays after the calls.
The realigned-frame case keeps its local array indexed by a runtime value so it
cannot shrink to a few scalars, and uses both call results in the independent
live-value checks.

The signature-join case exercises preservation of both the running signature and
the CFCSS predecessor adjustment across calls. Its helper overwrites `t0` and
`t4` explicitly on RISC-V, while native builds execute the same arithmetic and
volatile call counter. Independent literal results check both paths twice; the
counter also requires all 24 helper calls to execute.

The manifest selects the participating functions explicitly and enables machine
instruction verification. It exercises the unprotected configuration, each data
hardening mode, each control-flow mode and their combinations, using coarse-grained
scheduling. Failures should be recorded in the project test TODO without changing
the expected functional result.
