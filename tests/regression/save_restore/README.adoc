= GNU save/restore helpers and DMR spill policy

The signature-only RV32/RV64 cases enable `+save-restore` and apply CFCSS,
RASM or RACFED with DMR disabled. Each executable links the GNU toolchain's
real `__riscv_save_*` and `__riscv_restore_*` implementations from `libgcc`.

The leaf case has no source-level call; an empty assembly statement with explicit
callee-saved clobbers forces spills and therefore the compiler-generated helpers.
The other cases retain values across repeated ordinary calls, exercise several source
returns, and place register use in a cold branch that could otherwise receive
a shrink-wrapped prologue. The ordinary helper deliberately overwrites `t0`.
Three volatile inputs run twice against literal arithmetic results.

The manifest's `save_restore_functions` lists the protected functions in which
both a save-helper transfer and a restore-helper transfer must actually appear.
The shared runner checks normal and machine-verifier assembly and retains
`save-restore.json` and `save-restore.verify.json` as evidence. An ordinary
inline prologue cannot satisfy this check.

[,bash]
----
python3 tests/regression/run.py --case 'save_restore/*'
----

References enable the same helper-based ABI without signature monitoring.
Every successful executable exits with `42` and produces no output. The original
four cases select signature monitoring only.

== DMR with explicit callee saves

The link:dmr/suite.json[DMR cases] request the same save/restore target profile.
Selected DMR functions use explicit callee-saved spills and restores, which the
existing DMR instrumentation can protect. Ordinary functions retain the GNU
helpers. These cases use pure C and retain frame pointers to force callee-saved
register use without protected inline assembly.

Coverage includes a leaf, repeated calls with live state, return paths, a cold
branch, twelve integer arguments, a VLA and a realigned VLA. The stack-argument
and dynamic-frame cases select an ordinary or protected callee separately.
Every case also calls an ordinary control function from the same translation
unit and checks its literal result. This function must retain actual GNU helper
transfers while the selected DMR functions have none.

The matrix selects all five DMR modes and both schedules on RV32/RV64. Three
representative cases also select each CFP mode, and a repeated-call case enables
REPAIR for the NZDC modes. Normal and verifier assembly reports record the
per-function policy: `gnu_helpers` or `explicit_spills`. Explicit-spill evidence
requires an FP save/restore and, for nonleaf functions, an RA save/restore.

[,bash]
----
python3 tests/regression/run.py --case 'save_restore_dmr/*'
----
